    Getting started

    DBDock is a macOS desktop client for MySQL, PostgreSQL, SQLite, Redis, MongoDB and Cloudflare D1. It brings connections, SSH tunnels and database tools together in one place, with support for Vim, light and dark themes, and multiple languages.

    1. Add a connection: ⌘N, or + New connection. Pick the database type, fill host, user and password, and press Test.
    2. Or import the ones you already have: ⌘O (TablePlus, DBeaver, connection URLs, a DBDock export).
    3. Connect: double-click a card, or hover it and press Connect. Each connection opens as a tab at the top; ⌘1 goes back to the list.

    Saved passwords are stored in the macOS Keychain, and the form shows unchanged (saved in Keychain) instead of the value. Exports can include passwords; use a passphrase to encrypt them.

    Connections and groups

    Groups

    Groups are folders, and they can be nested with / , e.g. Acme / AI. Manage them in the sidebar:

    • New group: the folder button next to Groups, ⇧⌘N, or right-click a group → New subgroup….
    • Rename or move: right-click → Rename / move…. Type a parent in front to nest it; subgroups and connections move along.
    • Delete: right-click → Delete group…, then choose where its connections go (empty = Ungrouped). Connections are never deleted with a group.
    • Move connections: hover over a card and drag the handle that replaces its database icon onto a sidebar group. The target highlights before you release. You can also use Move to group… from the card menu or selection bar; typing a new name creates the group.

    Selecting several

    Click the round badge in a card's top-right corner, or ⌘-click cards. While a selection is active, clicking any card toggles it. The bar above the grid moves, exports or deletes them together. To clear the selection: Clear selection or × in that bar, Esc, or a click on empty space between the cards.

    Hover a card for Edit, ⋯ (more actions) and Connect at its bottom-right; double-click connects too.

    Environment tags

    LOCALDEVTESTSTAGINGPROD

    Set the tag in the connection form. Each option uses its environment color for its border and text; the selected option has a solid background. The tag shows on the card and on the session tab, and the chips above the grid filter by it. Production connections get a red outline and a red line on their tab, so you know where you are before you run an UPDATE.

    Connection health

    Choose Batch check shown to check the current list, or select cards and choose Check selected. The dialog identifies missing required settings; choose Batch test to test connections with complete settings. It runs up to four tests at once and may request Keychain access.

    Stopping cancels waiting tests and lets running tests finish. Results show success or an error, and the latest result appears on the connection card. Edit or delete a connection from the dialog when testing is not running. A missing SQLite file is reported without creating it.

    Import and export

    File → Import… (⌘O) works out the format by itself:

    SourceWhat comes along
    DBDock export (.json)Everything, including passwords if they were exported. Encrypted files ask for the passphrase.
    TablePlus Connections.plistConnections, groups, tags, SSH settings. Offered directly when TablePlus is installed. Passwords stay in TablePlus: it keeps them where other apps cannot read them, so enter each one once.
    DBeaver data-sources.jsonConnections, folders, connection types, SSH tunnels. Passwords stay in DBeaver.
    Connection URLs, .env, textEvery URL found, including its password. Also File → Paste Connection URLs… (⇧⌘I).
    DATABASE_URL=postgres://user:pass@db.example.com:5432/app
REDIS_URL=redis://:secret@127.0.0.1:6379/0
mongodb+srv://me:pw@cluster0.example.mongodb.net/shop
mysql://root@127.0.0.1:3306/shop
sqlite:///Users/me/data/app.db
jdbc:postgresql://localhost/app

    Importing the same source again updates the existing connections instead of adding copies. .env keys become the connection names.

    Export

    File → Export… (⇧⌘E) writes all connections, or the selected ones. With Include passwords on, set a passphrase: the file is then encrypted (AES-256-GCM, key from Argon2id). Without a passphrase the passwords are in plain text; the file is written readable only by you, but delete it once it has been imported.

    SSH tunnels

    Turn on Over SSH in the connection form to reach a database through a bastion. The database host and port are then resolved on the SSH server: use 127.0.0.1 for a database on that machine, or the private address of an RDS instance.

    • Agent / ~/.ssh (default): tries ssh-agent, then IdentityFile from ~/.ssh/config, then ~/.ssh/id_ed25519, id_ecdsa, id_rsa.
    • Key file: a specific private key; fill Passphrase if it is encrypted.
    • Password: SSH password login.

    The Server field accepts a Host alias from ~/.ssh/config; the Hosts button lists them, and the line below shows what the alias resolves to. When a typed host and user match an existing alias, the form offers to use the alias, so later edits to the config apply here too.

    Host keys must already be trusted in ~/.ssh/known_hosts. Verify and accept a new host with OpenSSH first; unknown, changed, unreadable, and certificate host keys are refused.

    ProxyJump is not followed by DBDock tunnels yet. Point the connection at the last hop directly.

    SSH Hosts

    Open it with File → SSH Hosts… (⇧⌘H). It edits ~/.ssh/config, the same file ssh uses.

    • Pick a host to edit HostName, User, Port, IdentityFile, ProxyJump; New host adds one; Test login signs in with the agent or keys.
    • Only those lines of that block change. Comments, other directives (ForwardAgent, ServerAliveInterval, …) and indentation are kept and listed under Kept as is.
    • Raw file edits the whole file, for Host *, multi-alias blocks, Match and anything else.
    • Every save first writes ~/.ssh/config.dbdock-<date>.bak.
    • The number next to a host counts the DBDock connections that use it.

    MySQL, PostgreSQL, SQLite, D1

    Browsing

    Pick a database / schema in the sidebar, then a table. The Data view pages through rows; type a WHERE condition (column names complete, Enter applies) and click a column header to sort. Structure lists columns, types, defaults and keys.

    SQL editor

    • ⌘↵ runs the selection, or everything. Several statements give several result tabs.
    • Completion knows tables, and the columns of the tables in the statement; Tab or Enter accepts.
    • Cancel stops a running MySQL or PostgreSQL query. SQLite and D1 cannot be cancelled.
    • One session is one connection, so USE, SET and transactions behave like an interactive console.

    Editing rows

    Tables with a primary key can be edited in the grid: double-click a cell (Enter saves, Esc cancels), + Row, − Row, NULL. Changes stay pending (yellow, struck-through, green) until you Commit (⌘S). Preview SQL shows exactly what will run.

    A commit runs in one transaction. If any UPDATE or DELETE does not hit exactly one row (someone changed it, or the key is not unique), nothing is changed.

    Cloudflare D1

    Fill the Account ID, Database ID (see wrangler d1 list) and an API token with the D1 Edit permission. Queries go through the Cloudflare REST API. D1 has no BEGIN; DBDock still commits grid edits atomically by sending them as one request.

    StarRocks, Doris and other MySQL-compatible servers

    Use the MySQL type. DBDock only sends SET NAMES when it connects, which these servers accept.

    Redis

    • The key list uses SCAN with a pattern (user:*); Load more… continues the scan.
    • Selecting a key shows its value by type (string, hash, list, set, sorted set, stream) with TTL and size; JSON strings are pretty-printed.
    • Switch databases with the db0–db15 menu or SELECT n.
    • The console at the bottom runs any command; ↑ / ↓ walk the history.

    MongoDB

    Connect with host and port, or paste a mongodb:// / mongodb+srv:// URI into Host. Options takes a query string such as authSource=admin&tls=true. Over SSH, use host and port rather than a URI.

    Collections

    Open a collection from the sidebar. filter, sort and projection accept the shell's relaxed syntax:

    { age: { $gt: 18 }, name: /^a/ }        filter
{ _id: -1 }                              sort
{ name: 1, email: 1 }                    projection
{ _id: ObjectId("65a1b2c3d4e5f60718293a4b") }
{ at: { $gte: ISODate("2026-01-01T00:00:00Z") } }

    Switch between Table and JSON, double-click a document to edit it as Extended JSON ({"$oid": …}, {"$date": …}), + Insert adds one. The _id of an existing document cannot be changed.

    Shell

    ⌘↵ runs the current line or the selection:

    db.users.find({ age: { $gt: 18 } }, { name: 1 }).sort({ age: -1 }).limit(20)
db.users.findOne({ name: "alice" })
db.orders.aggregate([{ $group: { _id: "$city", n: { $sum: 1 } } }])
db.users.countDocuments({})        db.users.distinct("city")
db.users.insertOne({ name: "dave" })
db.users.updateMany({ active: false }, { $set: { archived: true } })
db.users.deleteOne({ _id: ObjectId("…") })
db.runCommand({ dbStats: 1 })
show dbs        show collections        use otherdb

    Vim mode

    Turn it on in DBDock → Settings… (⌘,). It applies to the SQL editor, the Mongo shell, the document editor and the raw SSH config editor; a VIM badge shows where it is active.

    • Esc leaves insert mode, and closes an open completion list at the same time.
    • :w saves in the document and config editors, and runs in the SQL editor and shell.
    • Esc inside an editor never closes the dialog around it.

    Troubleshooting

    macOS keeps asking for Keychain access

    Keychain entries trust the signature of the app that saved them. A differently signed build (for example a development build) asks on every read, and Always Allow does not stick. Use the installed app; if entries were written by another build, export your connections with passwords from the build that can read them and import them again.

    "password authentication failed" after an import

    TablePlus and DBeaver do not share their passwords. Open Edit on the connection and type the password once.

    SSH: "host key rejected"

    The host key may be unknown, changed, unreadable, or a certificate. Verify new hosts with OpenSSH first. If a key change is expected, verify it, remove the old entry with ssh-keygen -R host, and verify the new key with OpenSSH.

    MySQL-compatible server refuses the connection

    Check the port (StarRocks and Doris usually listen on 9030) and that the user may connect from your address, or through the tunnel's server.

    A table is read-only

    Grid editing needs a primary key, so rows can be targeted safely. Views are always read-only. Use the SQL editor instead.

    Nothing matches.
